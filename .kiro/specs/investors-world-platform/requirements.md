# Requirements Document

## Introduction

Investors World Realty is a full-stack MLM (Multi-Level Marketing) real estate platform that enables associates to join under sponsors, build binary tree teams (left/right placement), earn multi-type commissions (direct, level, matching, reward income), and facilitates real estate property sales. The platform consists of a Backend API (Node.js + Express + Prisma + PostgreSQL), an Admin Panel (React + Vite + Tailwind CSS), and a Landing Site (Next.js + Tailwind CSS). A Flutter mobile app (built by a separate developer) will consume the same APIs.

## Glossary

- **API_Server**: The Node.js + Express backend application serving RESTful endpoints for all clients
- **Admin_Panel**: The React-based web application for platform administrators
- **Landing_Site**: The Next.js public-facing website for marketing and property showcase
- **Associate**: A registered user/member of the MLM network who can sponsor others and earn commissions
- **Sponsor**: An existing Associate who refers a new Associate to join the network
- **Binary_Tree**: The organizational structure where each Associate has at most two direct placements (left leg and right leg)
- **Placement**: The position (left or right) assigned to a new Associate under their upline in the Binary_Tree
- **Upline**: An Associate positioned above another Associate in the Binary_Tree hierarchy
- **Downline**: All Associates positioned below a given Associate in the Binary_Tree hierarchy
- **Package**: A membership tier that an Associate purchases to activate their account and determine commission eligibility
- **Direct_Income**: Commission earned when a personally sponsored Associate activates their Package
- **Level_Income**: Commission earned from Associates at various depth levels in the Binary_Tree
- **Matching_Income**: Commission earned based on the business volume generated by paired legs in the Binary_Tree
- **Reward_Income**: Bonus income earned upon achieving specific business milestones
- **Wallet**: A virtual account holding an Associate's available balance for fund transfers and withdrawals
- **KYC**: Know Your Customer verification requiring PAN card, Aadhaar card, and bank account details
- **Payout**: The disbursement of earned commissions to an Associate's bank account or Wallet
- **OTP**: One-Time Password sent via SMS or email for identity verification
- **Redis_Cache**: The Redis instance used for caching, session storage, OTP storage, and rate limiting
- **Auth_Token**: A JWT (JSON Web Token) used for authenticating API requests
- **Firebase_Cloud_Messaging**: Google's Firebase Cloud Messaging (FCM) service used for delivering push notifications to mobile and web clients
- **Firebase_Admin_SDK**: The server-side Firebase SDK used by the API_Server to send push notifications and manage device tokens
- **Device_Token**: A unique token generated by Firebase on each client device, used to target push notifications to specific devices
- **Soft_Delete**: A deletion strategy where records are marked with a deletedAt timestamp rather than being permanently removed from the database
- **Spillover**: The mechanism by which a new Associate is placed in the next available position in the specified leg when the immediate position is occupied

## Requirements

### Requirement 1: Associate Authentication

**User Story:** As an Associate, I want to securely log in, recover my password, and manage my session, so that my account remains protected and accessible.

#### Acceptance Criteria

1. WHEN an Associate submits valid User ID and Password credentials, THE API_Server SHALL authenticate the Associate and return an Auth_Token with a refresh token
2. WHEN an Associate submits invalid credentials, THE API_Server SHALL return an authentication error without revealing which credential is incorrect
3. WHEN an Associate requests a password reset, THE API_Server SHALL generate an OTP and send it to the registered mobile number or email
4. WHEN a valid OTP is submitted within 5 minutes of generation, THE API_Server SHALL allow the Associate to set a new password
5. IF an OTP submission exceeds 5 minutes from generation, THEN THE API_Server SHALL reject the OTP and require a new OTP request
6. IF an Associate fails authentication 5 times consecutively, THEN THE API_Server SHALL lock the account for 30 minutes
7. WHEN an Associate requests logout, THE API_Server SHALL invalidate the current Auth_Token and refresh token
8. THE API_Server SHALL store OTP values in Redis_Cache with a 5-minute expiration
9. WHILE an Auth_Token is expired, THE API_Server SHALL reject all requests with a 401 status code and prompt token refresh
10. WHEN a valid refresh token is submitted, THE API_Server SHALL issue a new Auth_Token without requiring re-authentication

### Requirement 2: Associate Dashboard

**User Story:** As an Associate, I want to view my key financial metrics, account details, and quick actions on a single dashboard, so that I can monitor my business at a glance.

#### Acceptance Criteria

1. WHEN an authenticated Associate requests the dashboard, THE API_Server SHALL return the Associate's last payment amount, total payments received, self-invested amount, and total network amount
2. WHEN an authenticated Associate requests the dashboard, THE API_Server SHALL return the Associate's joining date, activation date, Package name, PAN number (masked), and total activations count
3. WHEN an authenticated Associate requests advance payment status, THE API_Server SHALL return credit amount, debit amount, and current balance
4. WHEN an Associate requests the welcome letter, THE API_Server SHALL generate and return a downloadable PDF document containing the Associate's registration details
5. WHEN an authenticated Associate requests a referral link, THE API_Server SHALL return a unique URL containing the Associate's User ID for sharing
6. WHEN an authenticated Associate requests a referral QR code, THE API_Server SHALL generate and return a QR code image encoding the Associate's referral link
7. WHEN an Associate uploads a profile picture, THE API_Server SHALL validate the file is an image (JPEG, PNG) under 2MB and store it

### Requirement 3: Associate Profile Management

**User Story:** As an Associate, I want to view and update my personal, banking, and KYC details, so that my records remain current for payouts and compliance.

#### Acceptance Criteria

1. WHEN an authenticated Associate requests their profile, THE API_Server SHALL return all personal details including name, email, phone, address, sponsor ID, and placement information
2. WHEN an Associate submits profile updates for editable fields (phone, email, address), THE API_Server SHALL validate and save the changes
3. WHEN an Associate uploads a new profile photo, THE API_Server SHALL replace the existing photo and return the updated URL
4. WHEN an Associate submits bank details (account number, IFSC, bank name, branch), THE API_Server SHALL save the details with a pending KYC verification status
5. WHEN an Associate submits PAN card details with a document image, THE API_Server SHALL save the details with a pending verification status
6. WHEN an Associate submits Aadhaar card details with a document image, THE API_Server SHALL save the details with a pending verification status
7. THE API_Server SHALL restrict Associates from editing their name, date of birth, sponsor ID, and placement after initial registration

### Requirement 4: Genealogy and Team Structure

**User Story:** As an Associate, I want to visualize my binary tree network, view downline details, and filter team members, so that I can track my team's growth and performance.

#### Acceptance Criteria

1. WHEN an authenticated Associate requests the tree view, THE API_Server SHALL return the Binary_Tree structure starting from the Associate's position with configurable depth (default 5 levels)
2. WHEN an Associate requests downline members, THE API_Server SHALL return a paginated list of all Associates in the Downline with their status, joining date, and Package
3. WHEN an Associate requests sponsor details, THE API_Server SHALL return the Sponsor's name, User ID, phone number, and email
4. WHEN an Associate filters team members by status (active/inactive), THE API_Server SHALL return only members matching the specified status
5. WHEN an Associate filters team members by leg (left/right), THE API_Server SHALL return only members in the specified leg of the Binary_Tree
6. WHEN an Associate filters team members by level, THE API_Server SHALL return only members at the specified depth level
7. WHEN an Associate requests team business summary, THE API_Server SHALL return total business volume for left leg and right leg separately

### Requirement 5: Property Listings

**User Story:** As an Associate or visitor, I want to browse available real estate properties with details and images, so that I can make informed property investment decisions.

#### Acceptance Criteria

1. WHEN a user requests the property list, THE API_Server SHALL return a paginated list of properties with thumbnail image, name, location, price, and availability status
2. WHEN a user requests property details by ID, THE API_Server SHALL return full property information including all images, description, location, area, pricing, amenities, and booking status
3. WHEN an authenticated Associate submits a property inquiry, THE API_Server SHALL record the inquiry with Associate ID, property ID, and message, and notify the admin
4. THE Landing_Site SHALL display featured properties on the homepage with images, pricing, and location
5. WHEN a user applies filters (location, price range, property type), THE API_Server SHALL return only properties matching all specified filter criteria

### Requirement 6: Payout and Income Management

**User Story:** As an Associate, I want to view my earnings by income type, request withdrawals, and track payment status, so that I can manage my commission income effectively.

#### Acceptance Criteria

1. WHEN an authenticated Associate requests income summary, THE API_Server SHALL return total earnings broken down by Direct_Income, Level_Income, Matching_Income, and Reward_Income
2. WHEN an authenticated Associate requests income history, THE API_Server SHALL return a paginated list of all income transactions with date, type, amount, and source Associate ID
3. WHEN an authenticated Associate requests a withdrawal, THE API_Server SHALL validate the amount against available Wallet balance and create a pending withdrawal request
4. IF a withdrawal request amount exceeds the available Wallet balance, THEN THE API_Server SHALL reject the request with an insufficient balance error
5. WHEN an authenticated Associate requests withdrawal history, THE API_Server SHALL return a paginated list of all withdrawals with date, amount, status (pending/approved/rejected/paid), and transaction reference
6. THE API_Server SHALL calculate Direct_Income when a personally sponsored Associate activates a Package
7. THE API_Server SHALL calculate Level_Income based on the configured percentage for each level depth in the Binary_Tree
8. THE API_Server SHALL calculate Matching_Income based on paired business volume in left and right legs according to the configured plan rules
9. THE API_Server SHALL calculate Reward_Income when an Associate achieves a configured business milestone

### Requirement 7: New Associate Registration

**User Story:** As an existing Associate, I want to register new members under my sponsorship with proper placement, so that I can grow my network and earn commissions.

#### Acceptance Criteria

1. WHEN an Associate submits a new registration form, THE API_Server SHALL validate the Sponsor ID exists and is active
2. WHEN a valid registration is submitted, THE API_Server SHALL generate a unique User ID for the new Associate
3. WHEN a valid registration is submitted with placement preference (left/right), THE API_Server SHALL place the new Associate in the specified leg under the Sponsor or the next available position in that leg
4. WHEN a new Associate selects a Package and completes payment, THE API_Server SHALL activate the Associate's account and trigger Direct_Income calculation for the Sponsor
5. IF the specified placement position is already occupied, THEN THE API_Server SHALL place the new Associate in the next available position in the specified leg using a spillover mechanism
6. WHEN a registration is submitted, THE API_Server SHALL require mandatory fields: name, phone, email, address, PAN number, and Package selection
7. THE API_Server SHALL validate that the phone number and email are not already registered to another Associate

### Requirement 8: Wallet and Fund Management

**User Story:** As an Associate, I want to manage my wallet balance, transfer funds, and view transaction history, so that I can control my finances within the platform.

#### Acceptance Criteria

1. WHEN an authenticated Associate requests wallet details, THE API_Server SHALL return the current balance, total credits, and total debits
2. WHEN an Associate initiates a fund transfer to another Associate by User ID, THE API_Server SHALL validate the recipient exists, deduct from sender's Wallet, credit to recipient's Wallet, and record both transactions
3. IF a fund transfer amount exceeds the sender's available Wallet balance, THEN THE API_Server SHALL reject the transfer with an insufficient balance error
4. WHEN an Associate requests transaction history, THE API_Server SHALL return a paginated list of all Wallet transactions with date, type (credit/debit), amount, description, and counterparty
5. THE API_Server SHALL ensure all Wallet operations are atomic to prevent balance inconsistencies during concurrent transactions
6. WHEN a fund transfer is completed, THE API_Server SHALL send notifications to both sender and recipient

### Requirement 9: Notifications and Firebase Integration

**User Story:** As an Associate, I want to receive timely push notifications about payouts, registrations, property updates, and announcements on my mobile device and browser, so that I stay informed about platform activity.

#### Acceptance Criteria

1. WHEN an Associate logs in from a device, THE API_Server SHALL accept and store the Firebase device token associated with the Associate's account
2. WHEN an Associate logs in from multiple devices, THE API_Server SHALL store all device tokens and deliver notifications to all registered devices
3. WHEN a Payout is processed for an Associate, THE API_Server SHALL send a push notification to all of the Associate's registered devices via Firebase Cloud Messaging
4. WHEN a new Associate registers under a Sponsor, THE API_Server SHALL send a push notification to the Sponsor's registered devices
5. WHEN a new property is listed or an existing property is updated, THE API_Server SHALL send push notifications to all active Associates via Firebase Cloud Messaging topic subscription
6. WHEN an admin creates an announcement, THE API_Server SHALL deliver the announcement as a push notification to all targeted Associates via Firebase Cloud Messaging
7. WHEN an Associate receives a new income credit, THE API_Server SHALL send a push notification with the income type and amount
8. WHEN an Associate's KYC document is approved or rejected, THE API_Server SHALL send a push notification with the verification result
9. WHEN an authenticated Associate requests notification history, THE API_Server SHALL return a paginated list of notifications with read/unread status, title, message, type, and timestamp
10. WHEN an Associate marks a notification as read, THE API_Server SHALL update the notification status
11. WHEN an Associate logs out from a device, THE API_Server SHALL remove the Firebase device token for that device
12. THE API_Server SHALL use Firebase Admin SDK for server-side push notification delivery
13. THE API_Server SHALL support notification topics (all_users, package-specific, region-specific) for bulk messaging via Firebase Cloud Messaging

### Requirement 26: Mobile App API Contract

**User Story:** As a Flutter developer, I want well-documented RESTful APIs with consistent response formats, so that I can build the mobile app efficiently.

#### Acceptance Criteria

1. THE API_Server SHALL follow RESTful conventions with consistent JSON response format containing status, message, and data fields
2. THE API_Server SHALL return appropriate HTTP status codes (200 for success, 201 for creation, 400 for validation errors, 401 for unauthorized, 403 for forbidden, 404 for not found, 429 for rate limited, 500 for server errors)

### Requirement 27: API Security and Performance

**User Story:** As a platform operator, I want the API to be secure, performant, and scalable, so that the platform reliably serves 5000 concurrent users.

#### Acceptance Criteria

1. THE API_Server SHALL enforce HTTPS for all endpoints in production
2. THE API_Server SHALL validate and sanitize all input parameters to prevent SQL injection and XSS attacks
3. THE API_Server SHALL implement rate limiting using Redis_Cache to restrict each IP to 100 requests per minute for public endpoints and 300 requests per minute for authenticated endpoints
4. THE API_Server SHALL use JWT-based authentication with access tokens expiring in 15 minutes and refresh tokens expiring in 7 days
5. WHILE the platform is under load, THE API_Server SHALL maintain response times below 500ms for 95th percentile of requests when serving 5000 concurrent users
6. THE API_Server SHALL implement request pagination with a default page size of 20 and maximum page size of 100 for all list endpoints
7. THE API_Server SHALL cache frequently accessed read-only data (packages, property listings, dashboard metrics) in Redis_Cache with appropriate TTL values
8. THE API_Server SHALL run in PM2 cluster mode utilizing all available CPU cores on the production server
9. IF the API_Server encounters an unhandled error, THEN THE API_Server SHALL log the error with full stack trace and return a generic error response without exposing internal details

### Requirement 28: Database and Data Integrity

**User Story:** As a platform operator, I want data to be consistent, backed up, and properly structured, so that the platform maintains reliable records.

#### Acceptance Criteria

1. THE API_Server SHALL use Prisma ORM with PostgreSQL for all database operations
2. THE API_Server SHALL enforce referential integrity through foreign key constraints for all related entities
3. THE API_Server SHALL use database transactions for all multi-step operations involving Wallet balance changes
4. THE API_Server SHALL implement soft-delete (using a deletedAt timestamp) for Associates, Properties, and Transactions to preserve audit history
5. THE API_Server SHALL store all timestamps in UTC format
6. THE API_Server SHALL generate unique User IDs following the pattern "IW" followed by 6 sequential digits (e.g., IW100001)

### Requirement 31: Online Property Booking

**User Story:** As an Associate, I want to book a property online with payment, so that I can secure a property without visiting the office.

#### Acceptance Criteria

1. WHEN an authenticated Associate selects a property and initiates booking, THE API_Server SHALL create a booking request with Associate ID, property ID, and booking amount
2. WHEN an Associate completes payment for a booking, THE API_Server SHALL update the booking status to confirmed and update the property availability status
3. WHEN an Associate requests their booking history, THE API_Server SHALL return a paginated list of all bookings with property details, booking date, amount paid, and status (pending/confirmed/cancelled)
4. IF an Associate attempts to book a property that is already booked or sold, THEN THE API_Server SHALL reject the booking with a property unavailable error
5. WHEN an admin approves or cancels a booking, THE API_Server SHALL update the booking status and notify the Associate via push notification
6. THE API_Server SHALL generate a booking confirmation receipt as a downloadable PDF upon successful booking

### Requirement 32: EMI Calculator

**User Story:** As an Associate, I want to calculate EMI for property purchases, so that I can plan my finances before booking.

#### Acceptance Criteria

1. WHEN a user provides principal amount, interest rate, and tenure (in months), THE API_Server SHALL calculate and return the monthly EMI amount, total interest payable, and total payment amount
2. WHEN a user requests an EMI schedule, THE API_Server SHALL return a month-wise breakdown showing principal component, interest component, and remaining balance for each month
3. THE Landing_Site SHALL display an EMI calculator tool on the properties section allowing visitors to calculate EMI without authentication
4. THE API_Server SHALL use the standard reducing balance method for EMI calculation: EMI = P × r × (1+r)^n / ((1+r)^n - 1)

### Requirement 33: Video Property Tours

**User Story:** As an Associate or visitor, I want to view video tours of properties, so that I can evaluate properties remotely before visiting.

#### Acceptance Criteria

1. WHEN an admin uploads a video tour for a property (MP4 format, up to 100MB), THE API_Server SHALL store the video and associate it with the property listing
2. WHEN a user requests property details, THE API_Server SHALL include video tour URLs in the response if available
3. THE Landing_Site SHALL embed video tours on property detail pages with a video player supporting play, pause, and fullscreen controls
4. WHEN an admin uploads a video, THE API_Server SHALL validate the file format (MP4, MOV) and size (maximum 100MB) before storing

### Requirement 34: Multi-Language Support

**User Story:** As an Associate, I want to use the platform in my preferred language, so that I can navigate and understand the platform comfortably.

#### Acceptance Criteria

1. THE API_Server SHALL support localized response messages in English and Hindi as the initial supported languages
2. WHEN an Associate sets a language preference, THE API_Server SHALL return all user-facing messages, labels, and notifications in the selected language
3. THE Landing_Site SHALL support language switching between English and Hindi with all static content translated
4. THE Admin_Panel SHALL support language switching between English and Hindi for the admin interface
5. THE API_Server SHALL accept an Accept-Language header to determine the response language for unauthenticated requests

### Requirement 35: Commission Calculator

**User Story:** As an Associate, I want to calculate potential commissions based on team size and business volume, so that I can set goals and motivate my team.

#### Acceptance Criteria

1. WHEN an Associate provides projected direct referrals and team depth, THE API_Server SHALL calculate estimated Direct_Income, Level_Income, Matching_Income, and Reward_Income based on current plan configuration
2. WHEN an Associate requests a commission projection, THE API_Server SHALL return a breakdown by income type with assumptions clearly stated
3. THE Landing_Site SHALL display a commission calculator on the income plan page allowing visitors to estimate potential earnings without authentication
4. THE API_Server SHALL use the currently active income plan configuration for all commission calculations
